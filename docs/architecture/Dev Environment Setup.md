# StackAlchemist: Development Environment & Infrastructure Setup

> Updated 2026-10-03. There are two environments: local development and prod. No staging or test site exists (the test mirror `test.stackalchemist.app` and `deploy-test.yml` were retired on 2026-10-03, #211, PR #468). The database is qavren-db (Postgres) and sign-in is Qavren Auth (Keycloak). Supabase is legacy and rollback-only.

## 1. Domain & DNS (Cloudflare)
*   **Production Domain:** `stackalchemist.app`
*   **Auth Domain:** `auth.stackalchemist.app` (Keycloak, realm `stackalchemist`)
*   **SSL Mode:** Full (Strict)
*   **Bot Protection:** Bot Fight Mode enabled.

## 2. Storage Layer (Cloudflare R2)
*   **Buckets:** `stackalchemist-generations-dev` for local development and `stackalchemist-generations-prod` for prod. The CI E2E integration lane in `ci.yml` points at `stackalchemist-generations-test`.
*   **Access:** presigned download URLs generated by the Engine (default expiry 168 h, `CloudflareR2:PresignedUrlExpiryHours`). Open issue #444: ZIPs are also reachable through a public R2 custom domain.
*   **CORS:** allow `localhost:3000` and `stackalchemist.app`.

## 3. Database & Auth
*   **Database:** qavren-db, the shared Qavren Postgres (Supabase-hosted, reached through the Supavisor pooler), schema `stackalchemist`, with its own owning role.
*   **Migrations:** generated by `drizzle-kit generate` into `src/StackAlchemist.Web/drizzle/`, applied by `npm run db:migrate`. Prod applies them in the migrate step of `deploy-prod.yml` with `DATABASE_URL_MIGRATE`. Details: `docs/runbooks/qavren-db-migrations.md`.
*   **Auth:** Keycloak realm `stackalchemist` via Auth.js v5. Details: `docs/runbooks/qavren-auth.md`.

## 4. Local Development
Local dev needs a throwaway Postgres and a local Keycloak with the `stackalchemist-dev` realm. Follow the runbooks instead of duplicating them here:

*   **Postgres:** "Local database recipe" in [`docs/runbooks/qavren-db-migrations.md`](../runbooks/qavren-db-migrations.md). It starts a `postgres:17-alpine` container and runs `npm run db:migrate` against it.
*   **Keycloak, dev realm, test user and `.env.local`:** "Local recipe" in [`docs/runbooks/qavren-auth.md`](../runbooks/qavren-auth.md). It covers the qavren-auth compose, applying the `stackalchemist-dev` realm, creating a test user, and the `.env.local` the web app needs (`QAVREN_AUTH_URL`, `QAVREN_REALM`, `AUTH_SECRET`, `DATABASE_URL`).
*   **Demo mode:** with `NEXT_PUBLIC_DEMO_MODE=true` the web app runs without a database or Engine; the Playwright smoke suite uses it.
*   **Run:** `npm run dev` from `src/StackAlchemist.Web`; the Engine runs from `src/StackAlchemist.Engine` (`dotnet run`) or through the root `docker-compose.yml` (`sa-web`, `sa-engine`, `sa-worker`, reading `.env.development`). `.env.example` lists the variables.

## 5. Git Branching & Release Workflow
*   **Default Branch:** `main`. Work on a feature branch and open a PR; never push to `main` directly.
*   **Prod deploys:** every push to `main` deploys prod, except paths in the `paths-ignore` of `deploy-prod.yml` (docs, tests, CI-only workflows).
*   **Commit Standard:** [Conventional Commits](https://www.conventionalcommits.org/), required for the automated changelog.
*   **Release Automation:** `release.yml` runs `git-cliff` to update `CHANGELOG.md` and create a GitHub Release.

### CI/CD Compliance
*   **Frozen Lockfiles:** CI enforces `npm ci` for the frontend. Update `package-lock.json` before pushing or the "Frontend" quality gate fails.
*   **Docker Health Checks:** the `sa-web` and `sa-engine` images include `wget` for Docker Compose health probes. Preserve it across base image changes.

## 6. Containerization (Docker)
A multi-stage root `Dockerfile` supports all environments via build targets:
*   `web` (`sa-web`): Next.js frontend (includes `git` for build-time telemetry and `wget` for health checks).
*   `engine` (`sa-engine`): .NET 10 API (includes `wget`).
*   `worker` (`sa-worker`): .NET 10 Worker + Node.js. Not deployed; kept as a scale-out option because the Engine runs the compile worker in-process.

## 7. Production Environment (AWS EC2 + Docker + Cloudflare Tunnel)
*   **Region:** `us-east-1`
*   **Instance Type:** `t4g.small` (ARM64 / Graviton; `linux/arm64` images)
*   **Runtime:** Docker Compose (`docker-compose.prod.yml`) with `reverse-proxy` (nginx), `sa-web`, `sa-engine`. `cloudflared` runs as a standalone container on the same host, pointing at `reverse-proxy`.
*   **Deployment:** GitHub Actions on a self-hosted runner on the EC2 instance. SSH is for admin and break-glass fixes only.
*   **AWS access:** GitHub OIDC, no long-lived keys.

### Routing
One public domain, `https://stackalchemist.app/`, routed by `docker/nginx.prod.conf`:
- `/api/healthz`, `/api/auth/`, `/api/csp-report` and `/` go to `sa-web:3000`
- all other `/api/*` goes to `sa-engine:80`

### Deploy sequence
`deploy-prod.yml`: secrets preflight, qavren-db migrate step, build, swap behind a maintenance page, health checks, auth-mode check.
